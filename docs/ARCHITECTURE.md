# Architecture

YOMNOVA is a Rust workspace (`yomnova/`) plus a web app (repository root). Status of every stage is listed
honestly: *used* means the real pipeline calls it today.

## Compiler pipeline

```
source ─▶ lexer ─▶ parser ─▶ AST ─▶ sema (scopes + types) ─▶ ownership ─▶ codegen ─▶ bytecode ─▶ VM
                                                                  │
                                                          yomnova-ir  (lift → optimise → lower, on the emitted bytecode)
```

| Stage | Crate | Status |
|---|---|---|
| Lexing | `yomnova-lexer` | Used |
| Parsing (recursive descent + precedence climbing, nesting cap 150) | `yomnova-parser` | Used |
| Syntax tree | `yomnova-ast` | Used |
| Scopes, names, types, return paths, call checking | `yomnova-sema`, `yomnova-types` | Used (partial language coverage) |
| Move-based ownership | `yomnova-ownership` | Used (moves only) |
| IR + optimiser | `yomnova-ir` | Used. Lifts bytecode to a linear IR (jump targets are instruction indices), runs constant folding of `Int`/`Bool`/`Text` operations that cannot fail, dead push/pop removal, constant-condition jumps, jump threading and unreachable-code removal until nothing changes, then lowers it back. Chunks it cannot lift are left as they were. `--no-opt` skips it. The original 3-address/basic-block data types were removed: nothing used them. |
| Bytecode + disassembler | `yomnova-bytecode` | Used |
| AST → bytecode, driver, formatter | `yomnova-compiler` | Used |
| Stack VM | `yomnova-vm` | Used |
| Diagnostics (spans, rendering) | `yomnova-diagnostics` | Used |
| CLI | `yomnova-cli` (binary `yomnova`) | Used, no third-party dependencies |
| Network helpers | `yomnova-network-core` | **Not used** by the pipeline |
| Standard library | `yomnova-stdlib` | **Not used** by the pipeline |

`Compiler::check` runs lex → parse → sema → ownership. `Compiler::compile_unit` additionally generates bytecode
without executing it (used by `build`, `disasm`). `Compiler::compile_and_run` executes the result.
Errors are `Vec<Diagnostic>`. The parser recovers at statement/declaration boundaries, and sema and the ownership check continue after a failing statement; each stage reports its errors (max 20) and the next stage runs only when the previous one is clean. `yomnova-compiler::lint` then walks a valid AST and produces warnings.

## Bytecode and VM

* One `Chunk` per function plus an entry chunk holding top-level `const` initialisers and `main`'s body.
* 40 opcodes (`OpCode::ALL`, decoded safely by `OpCode::from_u8`; there is no `unsafe` in the workspace).
* Jumps and constant/slot operands are 16-bit; compilation fails with a clear error if a function exceeds them.
* `JumpIfFalse` pops its condition. `&&`/`||` compile to jumps (short-circuit), not to `And`/`Or` opcodes
  (those opcodes remain defined but unused by the code generator).
* Locals live in per-frame vectors; globals hold functions and constants. Pipelines compile to ordinary calls.
* The VM enforces: 1,000,000 steps, 65,536 stack slots, 10,000 call frames, 16 MiB text; integer arithmetic is
  checked (`IntegerOverflow`).
* `NetworkBuffer`/`Packet` values are created and read only through native functions that bounds-check every access.

## CLI

`yomnova run [-d] | check | build [-o] | disasm | tokens | ast | fmt [--check] | version | help`.
`build` writes a binary `.yomc` file (`yomnova-bytecode::module`: magic `YOMC`, format version 2, the opcode count, the entry chunk and the user functions) and `yomnova exec` runs it. Loading treats the file as untrusted: sizes and tags are validated, nesting and size are capped, trailing bytes are rejected, and the VM re-checks every operand at run time (step, stack, memory, call-depth and local-slot limits). A file is only valid for the opcode set it was built with; there is no compatibility layer and no signature.

## Web application

* `src/` — React 19 + TypeScript. `src/chapters/*` are the ten chapters; `src/lib/motion.ts` registers GSAP
  (ScrollTrigger, SplitText) once and provides `usePinnedSteps` / `useReveal`. Every animation sits inside
  `gsap.matchMedia()`: pinned, scrubbed storytelling only on desktop with motion allowed; on mobile and under
  `prefers-reduced-motion` chapters are plain, fully visible, scrolling content.
* `server.ts` — dependency-free `node:http` server. `/api/run|check|tokens|ast|disassemble|fmt` write the posted
  source to a private temp directory, run the real `yomnova` binary with a 5 s timeout, 1 MiB output cap and at
  most 4 concurrent jobs, and return its stdout/stderr. `/api/version`, `/api/examples` serve metadata and the
  files in `yomnova/examples/`. There is no OS-level sandbox.
* `server/ai/` + `/api/ai/*` — the optional AI Assistant (OpenRouter client, diagnostic adapter, documentation
  retrieval, response validation). Suggest-only; see [AI_ASSISTANT.md](AI_ASSISTANT.md).
* `public/brand/` — logo set generated by `scripts/generate-brand.py` (pure SVG paths, no fonts).
